# Audit reconciliation — 11 Oct 2026

Reconciles the application audit of 9 Oct 2026 (findings S1–S16, C1–C13, A1–A7, F1–F18, B1–B9, P1–P5, X1–X6, R1–R6) against the code on `dev` at `8252933c`. Investigation only: no application code, migration, dependency or data was changed.

## 1. How this was done

| What                  | Detail                                                                                                                                                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code state            | `dev` at `8252933c`, identical to `origin/dev` on 11 Oct. Uncommitted work at the time: `docs/development.md` plus untracked audit docs under `docs/`. None of it overlaps a proposed fix.                                                                                  |
| Method                | Five read-only code reviews (auth API, media/courses/learning API, commerce API, web auth/commerce, web UX/accessibility/hygiene), each tracing the current execution path, plus `git log`/`git show`/`git blame`. Two contested conclusions (C2, F9) were re-read by hand. |
| What was executed     | ESLint over `apps/web/src` and `packages/web-core/src` (no `--fix`): 6 errors, 32 warnings. Two isolated `node -e` evaluations of Zod schemas and Node crypto on empty inputs. `wc -l` and grep counts.                                                                     |
| What was not executed | No API server, database, browser, Lighthouse, build, typecheck, payment gateway or webhook. No `.env` file was read.                                                                                                                                                        |

**Status values.** `FIXED`, `PARTIALLY_FIXED`, `OPEN_CONFIRMED` (path traced, failure scenario still holds in code), `OPEN_UNVERIFIED` (looks open, needs a browser or runtime to confirm), `NOT_REPRODUCIBLE` (the described scenario cannot occur in the current code), `BLOCKED` (cannot be established without credentials or infrastructure).

**Basis values.** `Traced` = conclusion from reading the code path. `Evaluated` = a schema or function was run in isolation. `Lint` = ESLint run. Every `OPEN_CONFIRMED` below is a code-reading conclusion unless the basis says otherwise; no finding was reproduced against a running system in this pass.

### Facts that apply to every finding

- **No automated tests exist.** Commit `7192af5b` (9 Oct) removed every unit test and all test tooling. `apps/api/package.json` has only `typecheck` and `build`. Existing coverage for every finding is therefore none, and there is no runner to add API regression cases to. See section 8.
- **Very little of the audit has been fixed.** The "launch audit" commits of 9 Oct mostly pre-date the audit's observations. Only `b93d686d` (F4/F9), `777fa2e4` (F1) and `dc7f3b24` (F17) changed anything in scope, all partially. No commerce, media, courses or auth-server finding was fixed after the audit.
- **Unmapped database errors return 500.** `packages/api-core/src/errors.ts:126-170` has no mapping for pg `23505`/`23503`. This is the root of C13, B3, C6b and several auth races.
- **`apps/api/AGENTS.md` lists "checking account existence before consuming an OTP" as ordering to preserve.** S6/A1 must therefore add a non-consuming code check, not reorder the existing consume call.
